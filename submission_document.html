Step 2: Git Workflow Execution (4 Marks)

The version control workflow was executed sequentially to maintain an auditable, branching history:

1. Initial Project State Commit:

git add index.html about.html
git commit -m "Initial commit: Add index.html and about.html"
# Output: [main (root-commit) eac2ca6] 2 files changed, 52 insertions(+)

2. Modify File and Create Second Commit on Main:
Updated index.html to incorporate a dedicated "Key Objectives" section.

git add index.html
git commit -m "Update index.html: Add Key Objectives section"
# Output: [main 2d696df] 1 file changed, 9 insertions(+)

3. Create and Switch to feature Branch:

git branch feature
git checkout feature
# Output: Switched to branch 'feature'

4. Commit Feature Modifications to feature Branch:
Updated about.html to include a "Team & Workflow Features" section.

git add about.html
git commit -m "Add Team & Workflow Features section to about.html on feature branch"
# Output: [feature ab576c0] 1 file changed, 9 insertions(+)

5. Switch Back to main Branch:

git checkout main
# Output: Switched to branch 'main'

6. Merge Feature Branch into Main:
Executed with --no-ff to explicitly record the merge commit and preserve branch topology.

git merge --no-ff feature -m "Merge branch 'feature' into main"
# Output: Merge made by the 'ort' strategy. [Commit SHA: f496bf4]

Step 4: Undo Operation using Git (1 Mark)

Both standard local and remote undo operations were demonstrated and validated:

Method A: Local Undo via git reset HEAD~1

  1. Staged and committed test artifact test_reset.txt (Commit f4db6b7).
  2. Executed git reset HEAD~1.
  3. Observed Effect: The commit was unseated from HEAD and branch history rewound to 01850fa, preserving test_reset.txt in the local working directory as untracked.

Method B: Public History-Preserving Undo via git revert HEAD

  1. Committed temp_undo_feature.txt (Commit fbb0bde: "Add temporary feature file for undo demonstration").

  3. Observed Effect: Git recorded inverse commit 4c9c878 ("Revert 'Add temporary feature file for undo demonstration'") and deleted the file from the working tree. This provides a transparent, auditable history on GitHub.

GIT COMMANDS DOCUMENTATION - SDP ASSIGNMENT
Student / GitHub User: X-DIABLO-X
================================================================================

1. git init -b main
   Initializes a new Git repository locally in the current directory with default branch 'main'.
2. git config --global user.name ""
   Configures the global Git author username for commits.
3. git config --global user.email ""
   Configures the global Git author email address for commits.
4. git status
   Displays working tree status, showing staged, unstaged, and untracked files.
5. git add 
   Stages a specific file into the Git staging area for the next commit.
6. git add .
   Stages all new, modified, and deleted files across the working directory.
7. git commit -m ""
   Records a permanent snapshot of staged changes with a descriptive message.
8. git diff
   Inspects line-by-line differences between modified files and staged/committed state.
9. git branch feature
   Creates a new branch named 'feature' pointing to the current commit.
10. git checkout feature
    Switches active working tree and HEAD pointer to the 'feature' branch.
11. git checkout main
    Switches active working tree and HEAD pointer back to the 'main' branch.
12. git merge --no-ff feature -m ""
    Merges 'feature' into 'main' with a dedicated merge commit, preserving branch topology.
13. git log --graph --oneline --all
    Displays an ASCII graph of all commits, branch forks, and merges.
14. git check-ignore -v 
    Verifies which rule inside .gitignore is causing a specific file to be ignored.
15. git reset HEAD~1
    Undoes the most recent commit locally by rewinding HEAD, leaving files unstaged.
16. git revert HEAD --no-edit
    Undoes previous commit by creating a new inverse commit, preserving shared history.
17. git remote add origin 
    Binds the local repository to a remote repository hosted on GitHub.
18. git remote -v
    Displays URLs and aliases of all configured remote repositories.
19. git push -u origin main
    Pushes local 'main' branch commits to GitHub and sets upstream tracking.
20. git push origin feature
    Pushes local 'feature' branch to GitHub so branch history is visible remotely.
================================================================================

QUESTION 2: Test Case Design (10 Marks)

Application Scenario & Functional Requirements

Testing a standard authentication Login System composed of:

  • Username (Text Input field)
  • Password (Masked Text Input field)
  • Login button (Submission control)
Functional Requirements (FR) Traceability:
  • FR1: Username must not be empty.
  • FR2: Password must be at least 6 characters long.
  • FR3: Valid username and password allow a successful login.
  • FR4: Invalid credentials should display an error message.
  • FR5: After 3 consecutive failed login attempts, the account should be locked.

Test Design Methodology

  • Boundary Value Analysis (BVA): Targeted password length constraint (≥ 6 characters). Examined boundary acceptance at L = 6 (TC_02) and rejection at L = 5 (TC_05).
  • Equivalence Partitioning (EP): Partitioned input space into valid inputs, format violation inputs (empty strings, undersized strings), and invalid authentication data.
  • State Transition Testing: Modeled state transitions across consecutive failures: Active (0) → Active (1) → Active (2) → Locked (3) → Blocked Attempt → Reset on Success.
